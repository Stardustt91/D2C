Sheet A — As built

Current execution path

One cost parameter enters, one float leaves. Three queries produce a single concatenated text blob, which one prompt converts directly into a number — there is no intermediate representation of an individual price observation anywhere in the path.

Sheet B — Proposed

Evidence-based execution path

The single prompt is decomposed into collect → normalize → judge → aggregate. The atomic unit becomes the price observation rather than the final number, which makes every downstream control possible and every estimate reproducible from stored evidence.

P0

Resolve the item specification

Convert the parameter name into a structured spec — canonical item, category, price-driving attributes, required unit, region, import intensity. Serves as both the query seed and the matching key downstream.

new
P1

Query fan-out along named axes

Vary specificity, language, geography, source type and unit basis; generate eight to twelve, deduplicate, cap the budget. Agreement across independently phrased queries becomes a signal in its own right, feeding the confidence calculation at P6.

resolves D1
P2

Retrieve and fetch real content

Pull raw page content for promising hits rather than snippets alone, and use all returned results. Tag each source with a trust tier — vendor quote, marketplace, public tender, statistical bulletin.

resolves D2
P3

Extract structured price observations

One record per price found, not one number per parameter: raw value, currency, unit basis, quote date, verbatim item description, source URL and type, inclusions (VAT / installation / warranty / delivery), quantity tier, region — plus the verbatim sentence containing the number, which makes attribution checkable at P6.

resolves D3 — root cause
P4

Normalize each observation

Five independent adjustments, each logged as an explicit factor with a stated reason so the chain stays auditable: currency at the rate on the quote date; vintage escalated to present via an index; unit basis converted to the declared unit; scope stripped or grossed to one clean definition; quantity tier levelled.

For Egypt this is likely the largest single accuracy gain — the pound moved from roughly 15.7 to 50 per USD across 2022–24, and the correction differs by import intensity, since a prefabricated cabin tracks USD while a local wage does not.

resolves D4 resolves D5
P5

Grade SKU comparability

Score each observation against the P0 spec and classify it exact, equivalent, analogous or unrelated. Cheap string filter first, embeddings second, model judgment only on borderline pairs. Only exact and equivalent enter the primary estimate; analogous enters solely with a stated adjustment factor and a confidence downgrade.

resolves D6
P6

Aggregate robustly, verify, cross-check

Trimmed median with outlier rejection, weighted by source trust, match quality and recency, reported with an interquartile range rather than a bare point. Each citation is checked against the fetched text before it is kept. Internal historical actuals are normalized the same way and used as a sanity band and a disagreement flag. Confidence is computed from observation count, spread, match quality and vintage — not asked for.

resolves D8 resolves D9 resolves D10
P7

Abstention gate

Replace the forced float with an explicit status — estimated, insufficient_evidence, needs_analyst_input — gated on minimum qualifying observations, maximum spread and minimum match quality. When the gate fails, return what was searched and what was missing instead of a number, and surface it in the UI as a gap rather than a value.

resolves D7 resolves D11
P8

Cache observations, not answers

Key on the normalized item spec and unit rather than the raw parameter name, which otherwise yields a near-zero hit rate as names vary between runs. Store the observations themselves so that a moved exchange rate or an improved escalation model can be re-applied without re-searching. Time-to-live varies by volatility class: import-linked hardware ages fast, local labour slowly.

resolves D12
Sequencing

Suggested build order

Ordered by unblocking value rather than by stage number.

OrderStageRationaleScope
1 P3 — structured observations Prerequisite for most of the rest; contained refactor of a single function 1 function
2 P7 — abstention gate Largely deletion of harmful prompt instructions plus a status field prompt + schema
3 P4 — vintage and FX normalization Largest expected accuracy gain given Egyptian currency movement new module
4 P5 · P6 — matching and aggregation Depends on P3 records existing and P4 having levelled them new module
5 P8 — caching Easiest to build, but pays off least until the cached evidence is worth keeping store + TTL

Before any of it. Assemble a small set of parameters with known or agreed values and measure absolute percentage error, abstention rate and citation validity. Without a baseline there is no way to tell whether a change helped — and these failure modes are specifically the kind that survive a spot check.
